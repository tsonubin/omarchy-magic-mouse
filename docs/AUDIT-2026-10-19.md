# Audit 2026-10-19

Fresh audit of `omarchy-magic-mouse` for highest-value remaining work.
Branch `omp/improve-2026-10-19` (off `polish/ux`). Licensing and AUR
publishing are out of scope by instruction.

Method: full read of the runtime path (`evdev`, `pipeline`, `touch`,
`scrolling`, `actions`, `service`, `cli`), the install scripts, and the
docs; each finding is ranked by user-visible value and risk. Tests follow
`~/.omp/agent/skills/test-audit`: every new test must guard an observable
contract with a credible regression, one owner at the strongest boundary.

## Findings

### Robustness — devices and configs

| # | Finding | Severity | Verdict |
|---|---|---|---|
| R1 | **Action dispatch blocks the input loop.** `ActionDispatcher` runs `subprocess.run(timeout=2)` inside frame handling; a slow or hung `hyprctl`/`omarchy`/user command freezes pointer and scroll for up to 2s — the cursor hitch macOS never has. | high | implement: async spawn, completion logged on a worker thread |
| R2 | **Batched uinput writes can truncate.** `flush()` does one `os.write` on a **non-blocking** fd; a partial write (or `EAGAIN`) leaves a misaligned `input_event` stream — silent corruption that would garble everything after it. | high | implement: write-all loop with writability backoff |
| R3 | **Other virtual input devices get hijacked.** `should_manage` only excludes our own sink; a `ydotool`/input-remapper/uinput tool's virtual mouse looks like a wheel mouse and would be grabbed and re-emitted. Real hardware never reports `BUS_VIRTUAL`. | medium | implement: never manage `BUS_VIRTUAL`; make rig sources `BUS_USB` (realistic) |
| R4 | **Explicit `--config` on a missing path silently uses defaults.** Load-with-defaults is right for the implicit path, wrong for an explicit one. | medium | implement: error at the CLI |
| R5 | Wheel-mouse classification requires `REL_WHEEL`; a device advertising only hi-res wheel axes classifies as `other` and is left unmanaged. | low | implement (one condition) |
| R6 | Devices without axis resolution fall back to the Magic Mouse X scale (26 units/mm) for **both** axes; Y is 71 on real hardware, so mm thresholds skew ~2.7× on such devices. | low | **needs hardware** — any default is a guess |
| R7 | Two managed devices share one scroll pairing accumulator — reviewed: per-device engines feed a shared legacy/hi-res pairer, which is the correct single-virtual-mouse design. | note | no change |

### Errors and UX

| # | Finding | Severity | Verdict |
|---|---|---|---|
| U1 | **Config changes need a manual restart.** `SIGHUP` is ignored. Reloading (keep-old-on-invalid) is the standard daemon contract and removes real friction. | medium | implement |
| U2 | Doctor's `natural_scroll` double-flip warning fires whenever Hyprland flips — a false positive when the user set `scroll.natural=false` (one flip is correct there). | low | implement: warn only when both flips are active |
| U3 | `setup` (and its unit check) treats a packaged install — unit at `/usr/lib/systemd/user/` — as "not installed". | low | implement: check both paths |

### Install / uninstall

| # | Finding | Severity | Verdict |
|---|---|---|---|
| I1 | `install.sh` copies `__pycache__` into the install tree (dead weight; confusing diffs). | low | implement: exclude |
| I2 | `install.sh` uses `$USER` under `set -u` — aborts in environments without `USER` (cron, some service contexts). | low | implement: `id -un` fallback |

## Test plan (lean, per test-audit)

Four new tests total, each an observable contract with a credible regression
and no existing owner:

- actions do not block the caller (regression: reverting to synchronous run
  fails it), transport-free at the dispatch boundary.
- partial writes complete (regression: dropping the write loop fails it);
  real `os.pipe`, no mocks.
- `should_manage` table extension: `BUS_VIRTUAL` device not managed (extends
  the existing table; no new fixture).
- `SIGHUP` reload: observable scroll-direction change + keep-old-on-invalid
  (service boundary; device transport faked as in the existing churn tests —
  transport itself is owned by the rig).
- CLI: explicit missing `--config` errors instead of silent defaults.

Everything else in this audit is small enough that existing proof (unit
suite + 10 rig scenarios + sandbox install tests) covers regressions.

## Outcome

Implemented on this branch, one focused commit each: R1 (async dispatch —
plus deleting the `runner` test seam per test-audit), R2 (write-all under
backpressure), R3 (`BUS_VIRTUAL` policy), R4 (explicit `--config` must
exist), U1 (SIGHUP reload), U2/U3/R5 (doctor/setup/classify accuracy),
I1/I2 (install robustness), D1/D2 (docs). The rig caught two real defects
during the work: the reload left stale pipelines in the fd index (sign never
flipped), and spawn reaping broke under `SIGCHLD=SIG_IGN` — both fixed here.

New proof (lean): 4 tests — async dispatch at the real subprocess boundary,
write framing on a real pipe, extended `should_manage`/classify tables, and
the explicit-config error — plus one rig scenario (`config_reload`) owning
the reload lifecycle end to end.
